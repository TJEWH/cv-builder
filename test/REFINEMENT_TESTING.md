# Refinement and workspace regression tests

Fixtures use invented CVs, letters, private fragments, identifiers and proposals. They require no account, private backup or production credentials. The supported refinement workflow is connected, version 2; tests for retired manual imports and standalone drafting APIs have been removed.

## Node and build checks

Use Node 22+ and the installed repository dependencies:

```sh
npm test
npm run test:refinement
npm run refinement:prompts:check
npm run test:refinement-protocol
npm run build
```

The full suite includes workspace, document, privacy, export and storage tests. The focused suite covers refinement, structured operations, annotations and preview lifecycle. The build typechecks production code and browser fixtures. Generated task/protocol Markdown must match the current implementation; regenerate it with `npm run refinement:prompts` after intentional protocol edits.

[Prompt testing](refinementProtocol/README.md) documents offline MCP trace validation and optional live agent runs. Live runs require explicit fixture setup and cleanup; ordinary Node tests make no production calls.

## Browser checks

```sh
npm run test:e2e:serve
```

Open [the synthetic runner](http://127.0.0.1:5177/cv-builder/test/e2e/index.html) and click **Run all synthetic flows**. Success is **7/7 browser flows passed**. Each run starts fresh in-memory fixtures and leaves the final workspace visible.

| Flow | Behavior |
| --- | --- |
| `scope-layout` | Scope selection, visible task controls, scoped preview/editor and preparation settings |
| `scoped-history` | Questions-only current review, removed manual writing instructions, separate CV/letter history, letter-only reset, CV-only clear confirmation and preservation of letter history across reload |
| `cv` | Publish, sync an operation proposal, apply only to the application CV, compare, reload, save an approved independent variant |
| `initial-letter` | Publish an empty letter, apply its initial draft, compare and reload |
| `existing-letter` | Publish the complete current letter, apply a refinement, compare and reload |
| `proposal-review` | Automatic application, ignored annotation feedback, next iteration, reset and approved PDF generation |
| `template-questions` | Template groups and default expansion, frozen guidance and formatting, contextual questions, saved answer feedback, the next refinement, manual header size and reset to template defaults |

Use `?flow=cv` (or another listed ID) to isolate a flow; `?sidebar=1` exercises the desktop sidebar. A browser driver clicks `#run-tests` and waits for `body[data-result="passed"]` or `body[data-result="failed"]`. Read `#test-status` and `#test-results` for failures. Starting the Vite server does not execute tests.

The dedicated Vite configuration disables cloud configuration, does not load `.env` files, binds to loopback and restricts connections to its origin. It uses production Vue components, styles and vector PDF build plugins.

## Coverage boundaries

Node workflow tests execute the real workspace setup and composables with a minimal Vue renderer. They cover request generation, privacy projection, reconstruction, current history, approval concurrency, annotation feedback, local persistence, idempotency, stale baselines and failed commits. PDF provenance tests check exact renderer inputs; separate PDF tests inspect actual generated bytes.

Browser flows execute complete components, DOM controls, reactive previews, SVG rendering and vector PDFs. Supabase, authentication, clipboard and storage are synthetic. Reload tests remount from fixture memory; they do not prove browser-restart durability. Proposal content is synthetic and does not evaluate model drafting quality. Native file selection, production Auth/PostgREST and actual downloads need separate checks.

Database tests in [`supabase/tests`](../supabase/tests) exercise real functions and RLS with synthetic users and JWT claims. Each suite rolls back its fixtures. Run them explicitly after schema changes; `npm test` does not execute SQL or prove deployed permissions.

## Additional fixtures

- [Attachments](http://127.0.0.1:5177/cv-builder/test/e2e/attachments.html): click **Run attachment workflow**. Four checks cover manual metadata, application selection, actual PDF page order/sizes and missing-file export blocking. Files are synthetic `File`/`DataTransfer` objects; storage and cloud transport are in memory.
- [Job workspace](http://127.0.0.1:5177/cv-builder/test/browser/job-workspace.html): current opportunities/applications and connected proposal simulation. At a viewport no wider than 760px, `?flow=phone-filters` checks touch controls, filtering and navigation; inspect `body.dataset.filterTest`.
- [CV Studio](http://127.0.0.1:5177/cv-builder/test/browser/cv-studio.html): the complete app with synthetic storage and a sample CV. Check template selection, form scrolling, privacy replacements/exclusions and normal/privacy preview switching at desktop and phone widths. `?performance` records preview layout counts; `?stress` supplies a longer German CV.

Local attachment checks also run through `attachmentMetadata`, `localDocuments`, `localAttachmentsWorkflow` and `applicationPackage` Node tests. Opportunity checks cover filters, grouping, score/recency/deadline boundaries, receipts, account changes and private comments. The fixtures never read real browser CVs or cloud sessions.
